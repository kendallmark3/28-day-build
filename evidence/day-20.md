# Day 20 Evidence — Show architecture

Structured per `templates/evidence.md`.

## Intent tested
`days/day-20.md` (refined before building): add a "How it fits together" panel to the Overview view that shows the operating model Intent, Context, Build, Evidence, Review, Capability as an ordered flow, with a live count at each stage and a link to where the user works on it.

## Observed
- Intent check on `days/day-20.md`: "a capability/architecture view" and "a visual operating model" did not say what is drawn, whether it is live, or how it is made accessible. I decided: a live panel on the existing Overview view (no new nav item), an ordered list of six stages each with a description, a count from the stored data, and a link where a view exists; HTML and CSS only (no image, script, or external request); arrows generated by CSS with empty alternative text so assistive technology does not read them.
- Built: a pure `flowStages(state, contextCount)` in `app/logic.js` that returns the six stages with a large `count` and the words that follow it (`rest`); a `renderFlow` in `app/app.js` (the context count is read from the page's Project context list, so the two cannot disagree); and the panel and its styles.
- The stages read as sentences from the sample data: "3 saved, 2 ready", "7 files the app follows", "8 of 28 days done", "3 claims, 1 assumed", "1 review recorded", "1 of 2 promoted". Links: Intent to Intents, Context to References, Evidence and Review to Review. Build and Capability have no link, because their views (progress and capabilities) do not exist yet.
- **The screenshots caught two problems the first passing tests did not.** With six cards in one row inside the 720px panel, words broke mid-word ("Referen-ces", "Intent-s"), the columns were tiny, and the last card poked out of the panel. The counts also read "3 2 ready". I changed the flow to a stacked list with down arrows at every width (the phone layout had already read well), gave each count a sentence, and added a test that each card is wider than 250px. Everything else in the design stayed.
- Verified in real Chrome: 15 new checks pass in `day20.js` and the earlier suites pass: 297 of 297 in total. They cover the pure function (order, an empty project, the sample data, determinism on frozen input, no page or storage use); the panel's heading, caption, order, and descriptions; the counts matching the stored data and updating after a save and after relabelling a claim without a reload; the four links and each one opening its view; the ordered-list structure with no image, svg, or script and CSS arrows with empty alternative text; the four links reached by keyboard in order with outlines; stacked layout with no horizontal scroll at 1280px and 375px; and no request leaving the origin.
- Files changed: `app/logic.js`, `app/app.js`, `app/index.html`, `app/styles.css`, `context/architecture.md`, `days/day-20.md`, `intent/current-feature.md`, `evidence/checks/day20.js`, this record.

## Inferred
- A tests-only pass would have shipped a layout that was hard to read. Layout quality needs someone (or something) to look at the result.
- Showing the context count from the page keeps the diagram honest, but it means the Overview's number depends on the References view being present in the page.

## Assumed
- That an ordered vertical list is a good-enough "visual operating model" for a demo. It is not a diagram in the drawn sense.
- That leaving Build and Capability without links for now is acceptable; they gain links on Days 24 and 21.
- That the one-line descriptions of each stage are accurate summaries of how this app uses them.

## Deterministic checks
- [x] Syntax / build: `node --check` passes for both files.
- [x] Functional behavior: 15 new checks; 297 in total.
- [x] Validation rules: empty project and frozen input.
- [ ] Accessibility spot-check: list semantics, hidden arrows, keyboard, outlines checked; a screen-reader run was not made.

## What failed

## What was not checked
- Firefox and Safari support for the `content: "x" / ""` alternative-text syntax (browsers that do not support it may read the arrow). A very large count (thousands) in a narrow card.
