# 28-Day Roadmap

| Day | Focus | Product outcome |
|---|---|---|
| 1 | Baseline & product outcome | Define what IntentWorkbench is for |
| 2 | Prompt-to-intent | Convert vague feature asks into intent files |
| 3 | Success criteria | Make outcomes objectively checkable |
| 4 | Constraints | Prevent scope creep and unsafe changes |
| 5 | Stop conditions | Teach the workflow when to stop |
| 6 | Intent check | Add a repeatable preflight review |
| 7 | First usable slice | Ship the first coherent UI |
| 8 | Context map | Document architecture and domain terms |
| 9 | Curated context | Add non-goals, standards, and examples |
| 10 | Progressive intent | Improve from evidence instead of adding random scope |
| 11 | Data model | Add projects, intents, evidence, and capabilities |
| 12 | Persistence | Keep work in browser storage |
| 13 | Usability | Improve navigation and empty states |
| 14 | Challenge pass | Attack assumptions and weak behavior |
| 15 | Fresh-session review | Review against intent, not appearance |
| 16 | Evidence labels | Distinguish observed, inferred, and assumed |
| 17 | Deterministic checks | Add validation rules and readiness checks |
| 18 | Guardrails | Add control levels based on consequence |
| 19 | Failure handling | Make errors and incomplete states explicit |
| 20 | Architecture view | Add a system/capability map |
| 21 | Reusable skill | Package intent-check as a reusable skill |
| 22 | Review skill | Package evidence-first review |
| 23 | Capability ladder | Prompt → skill → trigger → workflow → capability |
| 24 | Metrics | Add reuse, completion, and trust signals |
| 25 | Onboarding | Make the app teach a new user without you |
| 26 | Polish | Improve accessibility, visual hierarchy, and responsiveness |
| 27 | Final adversarial review | Find what would embarrass you in a demo |
| 28 | Release | Ship, document, demo, and define the next intent |
