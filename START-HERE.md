# Start Here — 28 Days From Prompting to Capability

This repository is designed to be used, not merely read.

## The product you are building

**IntentWorkbench** is a lightweight engineering application for turning one-off AI work into durable assets. It lets a user:

- define project intent
- create feature intents
- organize context
- attach success criteria and stop conditions
- record evidence from implementation and review
- score readiness before a change is trusted
- promote repeated procedures into reusable capabilities
- keep a 28-day learning/build journal

The starter is intentionally small. The completed reference app shows what a strong Day-28 outcome can look like.

## Daily cadence

Plan for roughly **30–60 minutes per day**. A few build days may take longer.

Use this exact loop:

1. **Intent** — open today's file in `days/`.
2. **Intent check** — ask the AI to identify ambiguity, missing inputs, contradictions, and uncheckable criteria. Do not implement yet.
3. **Refine** — change the intent, not the output.
4. **Build** — implement only what the intent requires.
5. **Challenge** — ask where the result will fail and what assumptions were made.
6. **Verify** — use deterministic checks where possible and human review where judgment is needed.
7. **Evidence** — save what happened in `evidence/day-XX.md`.
8. **Commit** — keep the repository history as part of the learning.

## Progression

### Week 1 — Learn to specify
You move from vague prompting to clear, checkable intent.

### Week 2 — Build with context
You give the model better project context and improve the product using evidence from the previous run.

### Week 3 — Review and trust
You separate builder from reviewer, introduce evidence, guardrails, and deterministic checks.

### Week 4 — Turn repeated work into capability
You package reusable procedures, add operational thinking, and finish with a polished application and adoption plan.

## Important rule

Do **not** jump to the final reference implementation and copy it wholesale. Use it as a calibration target only after you attempt the day's intent.

A good outcome on Day 28 is not that your code matches the reference. It is that your repository clearly shows the progression:

**Intent → Result → Evidence → Refined Intent → Better Result**
